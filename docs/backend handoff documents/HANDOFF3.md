## 6. Dashboard Contract Normalization

Normalized control status vocabulary to:

- `pass`
- `warning`
- `fail`

Updated `src/lib/contracts/index.ts` and `docs/MVP_CONTRACT.md`.

Removed duplicate dashboard concepts from the backend dashboard response:

- Removed `controlCountsByStatus`.
- Removed separate `passCount`, `warningCount`, and `failCount`.
- Removed `connectorStatuses`.
- Removed `pendingPolicyAcknowledgementCount`.
- Removed `policyCompletionPercentage` as a top-level field.

The dashboard response now uses:

```ts
{
  generatedAt: string;
  lastDataRefreshAt?: string;
  overallCompliancePercent: number;
  controlCounts: {
    total: number;
    pass: number;
    warning: number;
    fail: number;
  };
  openRiskCount: number;
  openOffboardingIssueCount: number;
  policyMetrics: {
    completionPercentage: number;
    employeesWithPendingPolicies: number;
    totalMissingAcknowledgements: number;
  };
  connectors: Array<{
    id: string;
    provider: string;
    displayName: string;
    connectionStatus: "connected" | "disconnected";
    lastSyncStatus: "never_run" | "running" | "success" | "error";
    lastSyncedAt: string | null;
    lastError: string | null;
  }>;
  recentEvidence: Evidence[];
  unresolvedOffboardingIssues: OffboardingIssue[];
}
```

Required invariant:

```ts
controlCounts.total === controlCounts.pass + controlCounts.warning + controlCounts.fail
```

## 7. Connector State Model

Separated provider reachability from latest sync result:

- `connectionStatus: "connected" | "disconnected"`
- `lastSyncStatus: "never_run" | "running" | "success" | "error"`

Important Rippling behavior:

- Rippling is reachable in deterministic mock mode, so `connectionStatus` is `connected`.
- Rippling's latest sync intentionally reports `lastSyncStatus: "error"` because the mock data includes an unresolved offboarding checklist issue.
- Rippling no longer appears successful and failed for the same latest sync.
- `lastError` contains `One offboarding checklist item remains open.` for Rippling.

## 9. Observable Demo Sync State

Before this work, `POST /api/connectors/sync` returned deterministic mock results but did not visibly change subsequent dashboard responses.

Now, sync operations update in-memory backend state:

- Each sync uses the current server time by default.
- Tests can inject an execution timestamp to avoid flaky timing checks.
- Connector `lastSyncedAt` is updated.
- Connector `lastSyncStatus` is updated.
- Connector `lastError` is updated.
- Provider evidence `collectedAt` timestamps are refreshed.
- `syncRunHistory` is appended.
- Dashboard `lastDataRefreshAt` is updated.

`GET /api/dashboard` now uses:

- `generatedAt`: current response generation time.
- `lastDataRefreshAt`: latest completed demo sync timestamp.

This preserves deterministic findings and control outcomes while giving the frontend an observable state change for a "Run demo sync" button.

## 14. Known Limitations

- API data remains in-memory mock data, not Prisma-backed at request time.
- Demo sync state is process-local. Restarting the dev server resets it to deterministic initial values.
- Runtime sync results are not persisted to Prisma `SyncRun`.
- No live external provider calls exist.
- The auditor ZIP contains JSON and CSV data only; no screenshots, PDFs, or provider-native exports.
- `GET /api/auditor/export` now returns a ZIP download, while `AuditorExportResponse` remains in the shared contract as a legacy metadata type.

## 15. Frontend Integration Notes

- For the dashboard, use `controlCounts`, not `controlCountsByStatus` or separate count fields.
- Use `policyMetrics` for policy summary UI.
- Use `connectors[].connectionStatus` for provider reachability.
- Use `connectors[].lastSyncStatus`, `lastSyncedAt`, and `lastError` for sync display.
- Rippling should show as connected with latest sync error.
- After running `POST /api/connectors/sync`, refresh `GET /api/dashboard` and compare `lastDataRefreshAt` or connector `lastSyncedAt` to show that the sync completed.
- Do not infer official SOC 2 audit outcomes from any dashboard status; all values are demo-only.
